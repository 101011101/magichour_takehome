# Image-Generation Accuracy for Virtual Try-On: Research Synthesis

**Context:** Building a Colab that takes a person photo + garment photo and outputs the person wearing the garment (identity, pose, background preserved; garment patterns/logos/text faithful), which must beat a **Qwen-Image-Edit-2511** baseline. Assigned candidates: Krea 2, Ideogram, FLUX.2 Klein. Synthesis of ~25 research agents, August 7, 2026.

---

## 1. How Accuracy Mechanically Arises — and Where Fidelity Is Lost

All leading open-weight editors (Qwen-Image-Edit-2511, FLUX.1 Kontext / FLUX.2 family, Krea 2) are **latent flow-matching diffusion transformers (DiTs)**: they integrate a learned velocity field over N steps in a VAE-compressed latent space, decoding the final latent to pixels. Reference images are injected primarily by **in-context conditioning** — the reference's VAE latent tokens are concatenated into the transformer's token sequence, so every output token can attend directly to reference tokens (a "soft copy" mechanism). This is why modern editors preserve exact textures far better than older CLIP-embedding/cross-attention pipelines (LaDI-VTON, DCI-VTON), whose low-bandwidth semantic bottleneck provably loses logos and text.

**Qwen 2511's specific mechanics** (verified in the diffusers `QwenImageEditPlusPipeline` source): every input image goes through **both** paths of a dual encoding — the Qwen2.5-VL semantic path at only **~384×384-pixel area**, and the VAE reconstructive path at **~1024×1024-pixel area** — concatenated in list order, disambiguated by "Picture N" template labels, latent concatenation order, and per-image RoPE frame-index offsets. So image ordering and index-based prompting ("the person in Picture 1 wearing the garment in Picture 2") materially matter, and small garment logos are downsampled *twice* before generation begins.

Fidelity is structurally capped at distinct layers:

| Loss layer | Mechanism | Consequence for try-on |
|---|---|---|
| **VAE compression** | 8× spatial downsampling (~12× total for FLUX's 16-ch VAE, ~48× for SDXL) destroys sub-threshold detail at *encode* time — unrecoverable by any sampler setting | Small logo text, thin strokes, fine fabric weave blur before diffusion starts; degraded once on garment encode, again on output decode; multi-turn edits compound the loss |
| **~1MP working resolution** | Editing models auto-resize to ~1MP regardless of input; a chest logo on a full-body shot may occupy ~5–10 latent tokens | Crop/flat-lay the garment so details occupy more tokens — the single most controllable fidelity factor |
| **Attention dilution across references** | Multiple references cause identity entanglement, attribute swap, dominance, blending (MultiBind, arXiv 2603.21937) | Empirically confirmed: Qwen 2511 collapses from 6.10 → **2.35**/10 going from one garment reference to 2–4 (TStars-VTON) |
| **Full-frame regeneration** | Instruction editors re-render *everything*; "preserved" regions are reconstructions subject to drift ("Why Do DiT Editors Drift?", arXiv 2605.08250). Only **mask-based inpainting** copies unmasked latents and guarantees background/identity by construction | Face drift, background shift, pixel drift (Qwen has a documented few-pixel shift/zoom); paste-back compositing is the standard fix |
| **Distillation** | Step-distilled models (FLUX.2 klein distilled: fixed 4 steps, guidance 1.0) trade output diversity and tuning headroom for speed; losses cannot be undone at inference | Seed sweeps buy less variety; steps/guidance knobs become no-ops |
| **Seed variance** | Initial noise determines global layout and mode convergence; best vs worst seed spans FID 21.6 vs 32.0 (arXiv 2405.14828) | Best-of-N is a real, cheap accuracy lever |
| **Text rendering** | Legible glyphs require explicit training (Qwen's curriculum, Ideogram's typography focus). But garment text transfer is a *copy* task through the VAE bottleneck, not a rendering task — so T2I text specialists help less than strong in-context copy fidelity | Explicitly naming the logo text in the prompt lets the text head re-render it instead of copying blurred pixels (BFL: "naming the exact text gives it a target to render against") |

Autoregressive/unified models (Gemini "Nano Banana" family) are a different mechanism — discrete image tokens generated by an LLM backbone — with superb instruction adherence but weaker exact-pixel preservation (global re-rendering, slight skin-tone drift, occasional full-shot reframing).

## 2. Is It Tweakable? — The Layered Knob Map

Accuracy is tunable at every layer. Ordered from largest to smallest lever:

### Layer 0 — Model / endpoint choice (the biggest lever)
- **Dedicated VTON endpoints** (FLUX VTO v2, FASHN v1.6, Kling Kolors, Google virtual-try-on-001) beat general editors on garment fidelity — general editors "hallucinate garment details, drift on subject identity, and break down on fine-grained texture" (Oxygen-TryOn, arXiv 2607.21694: specialist 9.36 vs best general editor 8.77 single-item overall).
- Among general editors: **undistilled > distilled** for final quality; distilled variants are for cheap drafts only.
- **Garment-source routing matters enormously**: every model degrades sharply when the garment reference is *worn by another person* (Model2Model in VTEdit-Bench: Qwen 1.17, klein 1.03 vs >3.5 on shop/flat-lay images). Convert worn-garment photos to pseudo-packshots (segment/crop) before conditioning.

### Layer 1 — API / inference parameters
A critical distinction: **true CFG** (Qwen: `true_cfg_scale`, two forward passes, enables negative prompts) vs **distilled-guidance embedding** (FLUX.1-dev/Kontext: single pass; classic CFG > ~1.8 breaks these models). Porting numeric values between families is a top source of bugs. In diffusers Qwen pipelines, `guidance_scale` is a no-op — only `true_cfg_scale` does anything; fal's `guidance_scale` on the 2511 endpoint maps to true_cfg (confirmed by architectural elimination).

### Layer 2 — Conditioning inputs
- **Garment reference prep is the dominant controllable factor**: tight crop / flat-lay filling >80% of frame, plain background, ~1–2MP (up to 4MP for FLUX VTO), lanczos (never "area") resizing. Prefer packshots over on-model photos.
- **Exactly two references** (person first, garment second), addressed by index in the prompt. Extra refs cause attention dilution.
- **Person prep**: neutral, tighter-fitting source clothing reduces silhouette ghosting; optionally run a first "replace outfit with plain fitted grey t-shirt" pass.
- **Masks**: dilate 10–40px to cover the full extent of both old and new garment (too tight → old silhouette anchors the new garment; wrong sleeve lengths); Ideogram inpaint-v3 and Google VTO expose real masks; Qwen has a separate fal inpaint endpoint.
- **Pose control on Qwen**: 2509's skeleton-as-extra-image trick is reportedly **broken in 2511** (HF discussion #23, one cheap test cell settles it); hosted fallback is the AnyPose LoRA via fal's `/lora` endpoint (base+helper @0.7).
- **Multi-garment**: never feed Qwen 2511 multiple garment refs in one pass (2.35/10). Composite garments into one canvas (BFL's official recommendation) or chain sequential single-garment edits.

### Layer 3 — Prompting
- BFL's template, adopt cross-model: **"The person of image 1, maintaining exactly their face and pose, wearing the [detailed garment description] of image 2."**
- Qwen convention: prefix terse enumerated descriptions ("Picture 1: a woman in a park. Picture 2: a red floral midi dress."), then the instruction, then explicit keep-clauses ("Keep her face, hairstyle, pose, and background unchanged"). Verbose VLM-written captions *hurt*.
- **Transcribe garment text verbatim into the prompt** ('the black hoodie with "ACME RACING" across the chest') — this measurably recovers text the encoders blur.
- Precise verbs (replace, not add/transform); decompose complex swaps into sequential simple edits; disable prompt rewriters (`magic_prompt` OFF, `prompt_extend=false`) when literal adherence matters.

### Layer 4 — Post-processing
- **Paste-back compositing** — the only guarantee: segment the garment region (SAM/cloth parser), 10–30px dilated feathered mask, composite generated pixels inside / original pixels outside. Makes background drift and face drift near-zero by construction, defeats Qwen's pixel drift and the VAE round-trip color shift. Gate face paste-back on landmark alignment (skip if head moved > ~2–3% of image width).
- **Face swap fallback** (inswapper_128 + CodeFormer ~0.5, or fal `easel-ai/advanced-face-swap`) when pose changed; note inswapper is non-commercial.
- Crop-and-stitch second pass on the logo region; slight downscale-then-reupscale (0.75×) to kill Qwen's VAE halftone grid; round dims to multiples of 16 to stop pixel drift.

## 3. How to Search for a Solution — The Practitioner's Playbook

### Order of operations when output is wrong

First, **diagnose stochastic vs systematic**: rerun 3–4 seeds. If the failure varies by seed → resample and rerank. If it's identical across seeds → no seed budget will fix it; move down the ladder.

1. **Prompt hardening** (free): index-based references, preservation clauses, verbatim logo text, precise verbs, decomposition into sequential edits. Iterate on a *fixed seed*.
2. **Best-of-N with reranking** (cheap): N=4 is the sweet spot — Qwen's `num_images=4` does it in one call. Evidence: best-of-N gains are real but modest and model-dependent (ADE-CoT: +0.12 to +0.73 on a 10-pt edit scale even at N=32, concentrated on *hard* cases — i.e., it rescues the failure tail, exactly your garbled-logo/identity-drift cases). Diminishing returns past N≈8; structured selection at N=4 can beat naive N=8 (GridAR). Size N binomially from measured per-sample pass rate: N = ⌈ln(1−C)/ln(1−p)⌉ (p=0.3→N=7, p=0.5→N=4, p=0.7→N=2 at 90% confidence).
3. **Parameter grid** (only where knobs exist — effectively Qwen 2511 and flux-2-flex): fixed seed, sweep guidance {3, 4, 4.5, 5, 6} × steps {28, 40}, one variable at a time (XYZ-plot discipline). Set `acceleration="none"` for anything scored. Raise steps before guidance if detail is mushy; raise guidance if the garment isn't transferring; lower it if colors burn or the face drifts.
4. **Conditioning changes**: tighter garment crop / higher-res inputs, pseudo-packshot conversion, mask dilation, neutral-base-clothing pre-pass, canvas-merge for multi-garment.
5. **Model switch / routing**: route by garment-source type and garment class (logo-heavy → specialist; worn-garment source → FLUX.2/FASHN, never Qwen).
6. **Post-process repair**: paste-back, logo crop-and-stitch, upscale.

### The cheap eval loop

**Metric stack (per-region, never whole-image):**
- Garment fidelity: CLIP-I/**DINO** similarity on the *garment crop* vs the reference (DINO discriminates fine texture better).
- Text/logos: **OCR edit-distance** (VTBench FTS pattern, PPOCR + Levenshtein) — whole-image SSIM/FID demonstrably miss garment-fidelity failures.
- Identity: **ArcFace cosine** on aligned face crops (InsightFace buffalo_l). Bands: <0.35 fail, 0.35–0.55 drifted, ≥0.6 good; verification-grade "same person" is 0.30–0.45.
- Background: SSIM/LPIPS *outside* the person mask (pixel-diff catches drift that no aesthetic metric sees).

**VLM judge — the load-bearing detail:** don't ask for a holistic 1–10 score. Two independently validated protocols:
- **Min-rule** (VTEdit-QA): score model-consistency, cloth-consistency, image-quality 0–5 separately; overall = **minimum** — a pretty-but-wrong output can't win. Add a fourth text/logo axis.
- **Error enumeration** (arXiv 2603.05659): have the judge *list concrete defects* per axis (garment placement/length, color/pattern/texture, realism, lighting, source integrity) and pick the candidate with fewest errors — this recovers human top-1 preference **60% vs 30%** for naive direct scoring.
- Use a frontier VLM (GPT-4o class; open judges are much weaker per VIEScore, Spearman ~0.4 vs human ceiling 0.45). For pairwise A/B, randomize left/right order or query both orders and discard flipped verdicts (~5% residual position bias).
- Raw CLIP-score reranking is documented as unstable — don't use it alone. Watch verifier over-optimization at large N.

**Human A/B**: reserve for final model-vs-model verdicts on ~20–40 pairs; the automated stack triages everything else.

**Benchmark design** (fills a genuine public gap — no published head-to-head measures Qwen 2511 vs FASHN vs FLUX VTO on logo fidelity or ArcFace identity): ~10 people × ~10 hard garments (small-text graphic tees, plaid/stripes, sequins, asymmetric hems) × 3–4 seeds × each system ≈ 900 generations, roughly $20–45 per hosted arm. Fix each model at its native resolution; report **per-garment-category win rates**, not just averages — rankings invert by garment type.

## 4. What This Means for the Try-On Colab

### Per-model verdicts

**Qwen-Image-Edit-2511 (baseline)** — 20B Apache-2.0 MMDiT, ~$0.02–0.03/image hosted. Best-in-open-weights *cloth consistency* on single shop-garment try-on (**4.77**/5 in VTEdit-Bench — actually the highest of all 15 models tested) and strong character consistency, with the fullest hosted knob set. **Exploitable weaknesses:**
- Fine-texture smoothing: sequins/lace/skin go "plastic"; "lost most of the sequin information" (ionio).
- **Multi-reference collapse**: 2.35/10 multi-item (TStars), 0.34 MultiShop2Model (VTEdit) — worst of any benchmarked model.
- **Person-to-person garment transfer**: 1.17/10 overall from identity drift.
- Pixel drift, square-aspect washout, VAE halftone grid at high res, unreliable >2–3MP, input-blur propagation.
- Overall min-rule scores trail klein (3.64 vs 3.96 Shop2Model) because image quality and multi-view robustness drag it down.

**FLUX.2 Klein** — ✅ **Strong candidate.** Wins all three shop-based tasks in VTEdit-Bench (3.96/3.99/3.56 vs Qwen 3.64/2.46/2.14), beating even the best specialized open VTON model; community finds it sharper/faster on lace, hair, 2048px. Caveats: distilled endpoints are knobless (use **9B base/edit** on fal for guidance+steps+free negatives, or **flex/edit** for full sweeps); klein-4B is the only Apache-2.0 tier (9B is non-commercial); its Model2Model failure mode is reference confusion (1.03). *Real disagreement to note:* community anecdotes say "Qwen keeps identity better, klein keeps detail better," while VTEdit's judge gives klein higher model-consistency too — trust the benchmark direction but verify on your own ArcFace numbers.

**Krea 2** — ❌ **Excluded.** No hosted edit or image-to-image endpoint exists (text-to-image + style references only; fal endpoints reject image inputs). The only try-on path is a community ComfyUI LoRA whose own author calls outfit swaps "hit-or-miss," ≤2MP, served via a niche decentralized API (~$0.03/img on Sogni) — at most a curiosity arm.

**Ideogram** — ⚠️ **Weak fit; one exploratory cell at most.** The only endpoint that can accept person+garment together is "Edit with Prompt" ($0.20 flat — 7–10× a Qwen attempt — undocumented underlying model, zero published try-on evidence anywhere). Its masked inpaint-v3 preserves unmasked pixels but can only ingest the garment as a *style* reference (loses geometry/logos). Ideogram's typography strength doesn't transfer: garment text is a copy task, not a rendering task. Ideogram is absent from every try-on benchmark and community comparison.

### Recommended pipeline

**Architecture: hosted APIs from the Colab (API keys, no GPU wrestling), with routing + best-of-4 + judge selection + paste-back.**

1. **Preprocess.** Person and garment → ~1MP (lanczos, never <512px, dims to multiples of 16, non-square aspect matching the person photo). Garment → tight flat-lay crop, plain background; if only a worn photo exists, segment to a pseudo-packshot. OCR/transcribe any garment text.
2. **Route.**
   - Default arm: **FLUX VTO v2** (person+garment slots, seed sweeps).
   - Specialist arm: **FASHN v1.6** quality mode (set `category` explicitly — dresses = "one-pieces"; `garment_photo_type` explicit) for pattern/text-heavy garments; escalate to Try-On Max for 4K logo legibility.
   - General-editor arms: **Qwen 2511** (baseline: `acceleration=none`, steps 40, guidance 4.0–4.5, negative `" "` + targeted negatives, person=Picture 1) and **Seedream 5.0 Lite** and/or **FLUX.2 klein 9B base/edit** (guidance 4–5, steps 28+, free negative prompt).
   - Route swimwear/lingerie away from FLUX VTO (policy-blocked) and NBP; if using NBP, implement the editorial-photograph reframe-and-retry ladder.
   - Multi-garment: composite into one canvas or chain single-garment passes; never multi-ref Qwen.
3. **Sample.** Best-of-4 per arm (one call where `num_images`/`num_samples`/`max_images` exists; parallel seeded calls otherwise).
4. **Select.** VLM judge with **error enumeration** across five axes (garment transfer, attribute preservation, realism, lighting, source integrity) + OCR text match + ArcFace ≥0.6 gate + background-SSIM outside the person mask; pick min-error candidate. All four fail → prompt revision → guidance/steps grid (Qwen/flex only) → next arm.
5. **Post-process.** Paste-back composite outside the garment mask (feathered 10–30px) for background/identity guarantees; face paste-back gated on landmark alignment, face-swap fallback if pose moved; optional logo crop-and-stitch pass.

### Eval rubric (this doubles as the "beat the baseline" proof)

Score every output on five axes, **overall = min** (plus enumerated-error count as tiebreaker):

1. **Garment fidelity** — pattern/color/texture match (garment-crop DINO/CLIP-I + judge).
2. **Text/logo accuracy** — OCR edit-distance vs reference garment text.
3. **Identity** — ArcFace cosine (≥0.6 pass) + judge on face/hair.
4. **Pose & body** — unchanged pose, no extra limbs, correct garment length/fit.
5. **Background preservation** — SSIM/LPIPS outside the person mask.

Run the full grid (≈10 people × 10 hard garments × 3–4 seeds × arms, ~$20–45/hosted arm), report per-category win rates, and keep 20–40 pairs for a human A/B on the finalists. Given VTEdit-Bench (klein > Qwen overall), TStars (Seedream 5 Lite / GPT-Image-2 ≫ FLUX.2-dev ≥ Qwen), and the specialist-endpoint evidence, **beating Qwen 2511 is very likely via FLUX VTO v2 or FASHN with best-of-4 + paste-back** — but no public benchmark measures exactly this logo-fidelity/identity combination, so the Colab's own grid is the deciding (and genuinely novel) data.
