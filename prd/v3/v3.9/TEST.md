# v3.9 — TEST

The matrix, per [SCHEMA.md](../SCHEMA.md). Written before the run; a change to the set is a new
test.

## 1. The bound this test runs under

**Nothing in this run exceeds 1 MP.** Every photo is re-normalised to **≤ 2²⁰ = 1,048,576 px**
(`run_v39.normalise`) in place of v3lib's 1,150,000, and the A4 crops are **recomputed from the
bounded photos** rather than taken from the archive. Two consequences, stated rather than
buried:

- **Every arm is regenerated here**, the `SCALE` baseline included. The v3.8 archive was made
  on 1.15 MP inputs and BFL's transformer; comparing against it would vary three things at
  once. All three arms are built in this run on one pipeline.
- **The bald pass sees the bounded photo too**, so the references are rebuilt as well. That is
  the point: an arm and its baseline must differ in one thing only.

## 2. The arms

| arm | reference | call-2 canvas | answers |
|---|---|---|---|
| `SCALE` | bald pass on the bounded photo → `crop_bc` | **the rule of record** (`_size_fal`): area 2²⁰, aspect kept, **up** or down, floor 32 | the baseline both questions face |
| `NOSCALE` | `SCALE`'s | **no upscale**: the photo's own size, floor 32 (never upscaled, and past the bound never reduced) | [EXPERIMENT link 1](EXPERIMENT.md) |
| `CROP2` | `crop_a4` → bald pass on the crop → `crop_bc` | the rule of record | [EXPERIMENT link 2](EXPERIMENT.md) |

**Both canvases floor to 32**, so the variable between `SCALE` and `NOSCALE` is the up/down
scaling and not the rounding. `klein_local.edit` selects between its own two rules by name;
`NOSCALE`'s is neither, so the runner injects the canvas function around the call rather than
adding a third name to a module the runs of record share (`run_v39._canvas`).

Runner `v3/colab/lib/run_v39.py`; notebook `v3/colab/v39_a100.ipynb` (generated by
`v3/build/make_v39_notebook.py`); bundle `v39_bundle.zip` (`v3/build/make_v39_bundle.py`).

## 6. Review protocol

`python3 v3/build/v39_page.py v3/runs/v39/a100` → `v3/report/v39.html`. One card per
comparison — `SCALE` vs `NOSCALE` on the 68 non-no-op cells, `SCALE` vs `CROP2` on all 93 —
**161 cards**. Arm labels hidden; sides shuffled per card and cards shuffled, both at seed 46;
the group (`fail` / `clean`) hidden; image files hash-named so the page source does not name
the arm. One mark per card: **A better · same · B better · both bad**. Export →
`v3/testsets/v39_marks.csv`, carrying the unblinding key (`shown_A`, `shown_B`), the true
canvas sizes (`wh_A`, `wh_B`) and the resolved verdict (`arm_better`, `baseline_better`,
`same`, `both_bad`).

**The resolution tell, and what was done about it.** `NOSCALE`'s canvas is genuinely smaller,
so a reviewer could pick the arm by pixel count rather than by content. **Both sides are
resampled to the same display width (460 px), and the lightbox copies to the same width too**,
so neither the card nor a click reveals which canvas is which; the true sizes go to the CSV
instead. This is the one mitigation available short of not asking the question.

**The protocol's other weaknesses, stated before the run.**

- **`CROP2`'s card shows both references**, labelled by crop count — needed to judge the
  question, and a cue to which output used which.
- **One reviewer**, whose threshold moved 1.72× between two sittings in v3.8 (RESULTS §3):
  every judgement here is paired within one card, the instrument that survived that.
- **The fresh baseline is not the archive** — different transformer *and* different input
  bound. Notebook cell 9 prints its distance from the archive on the cells whose canvas did not
  move, as a sanity check only; it is not a marking input.
