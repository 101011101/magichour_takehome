## 1. The arms

| arm | call-2 canvas | rule |
|---|---|---|
| `SCALE` | the rule of record | area 2²⁰, aspect kept, scaled **up or down**, each side floored to 32 (`klein_local._size_fal`) |
| `NOSCALE` | the candidate | the person photo's own size under a 1 MP bound, each side floored to 32, **never upscaled** |

Both arms floor to **32**, so the variable is the up-scaling and not the rounding. `NOSCALE`'s
rule is injected around the call rather than added to `klein_local`, which is shared with every
run of record (`run_v310._canvas`).

## 2. The set

`v3/colab/v310_set.csv` — **600 cells** · 200 pairs × seeds 46/47/48.

The whole iron-man-2 matrix, unsampled and unfiltered: the same cells `BC`'s two blind counts
and `ER`'s were made on, so every cell already carries a verdict from a sweep that did not know
this question existed. Each row carries that verdict (`bc2`, `er`, and `prior` = fail if either
sweep failed it).

| | cells |
|---|---|
| prior verdict **fail** (either sweep) | 53 |
| prior verdict **clean** (both sweeps) | 547 |
| **no-ops** — person photo already at the bound, so both rules give one canvas | **144** |
| comparable cards: prior fail | **36** |
| comparable cards: prior clean | **420** |

**The no-ops are not a sample loss.** A photo already at or above 2²⁰ px is bounded to ~1 MP,
at which point "scale to 1 MP" and "leave it alone" are the same instruction. Those 144 cells
are identical under both arms by construction, are not generated, and are listed in the page
footer.

**Not poolable with v3.9.** v3.9 rebuilt its references under the 1 MP bound; this run uses the
archive's, built at 1.15 MP. Each run is internally consistent — an arm and its baseline always
share a reference — but a cell here is not the same image as a cell there, and the two sets of
marks must not be merged.

## 5. The review protocol

`v3/build/v310_page.py` → `v3/report/v310.html` → `v3/testsets/v310_marks.csv`.

- **One shuffled stream, one bar.** Every comparable card sits in a single shuffled list. The
  arm is hidden, the sides are shuffled per card at seed 46, the image files are named by hash,
  and **the prior verdict is not shown** — it rides in the card's data and the export and is
  applied at analysis time. Marking the passing cells in one sitting and the failing cells in
  another would reintroduce the drift that cost v3.8 its headline: the same reviewer's bar moved
  **1.72×** between two sittings on these very cells ([v3.8 RESULTS §3](../v3.8/RESULTS.md)).
- **Partial marking is still valid.** Because the order is shuffled, stopping part-way leaves a
  random sample of both groups rather than a biased slice. Marks persist across reloads.
- **The question is one line:** which of these two would you ship — or *same*, or *both bad*.
- **A shorter sitting, if wanted:** `--clean N` keeps N of the prior-clean cards, sampled at
  seed 46, and the footer and export record the denominator they were drawn from.

**The instrument's own weakness, stated in advance.** `NOSCALE`'s output is genuinely fewer
pixels. Both sides are therefore resampled to the same display width, and the lightbox copies
with them, so neither the card nor a click reveals which canvas is smaller — but a
lower-resolution image resampled up to a fixed width can still *read* differently, softer or
smoother, and that is a route by which the arm could be identified or unconsciously preferred.
This page cannot remove that; it can only stop pixel count from being the tell. Read any result
with it in mind, and treat a small margin as what it is.

**A second weakness carried from v3.8.** This is one reviewer. Nothing here is a second pair of
eyes, and the 1.72× sitting-to-sitting spread measured on these cells is the best available
estimate of the noise a single reviewer brings.
