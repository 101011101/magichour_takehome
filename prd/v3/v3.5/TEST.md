garments and 56 persons). Link A is a *reference* experiment: call 1 runs once per garment,
not once per pair, so the garment axis is the whole set and the person axis does not enter

## Link C's set — every pair either record marks hard

`v3/testsets/v35_linkC.csv` — **51 pairs**, the union of the two failure records that exist
for the 200-pair matrix. They overlap on only **11** pairs, which is the reason to take the
union rather than pick one:

| provenance | pairs | what it is |
|---|---|---|
| `v34_lock` | 20 | the **v3.4 lock's own** failures and not v3.3's — the reviewer's per-cell verdict on `VEi` (`v34_im2_truth.json`, 600 cells, 100% judged) |
| `v33` | 20 | **v3.3's** failures and not the lock's — from `v34_failures.csv`, carrying the `F1`–`F4` class |
| `both` | 11 | marked by both records |

Every row carries both records' per-seed verdicts (`lock46/47/48`, `v33_46/47/48`), the
v3.3 class where it has one, and both seed-stable flags. Generated by
`v3/build/make_v35_linkC_set.py`, not typed.

**On BC failures.** There is **no per-cell pass/fail record for a correctly built `BC`** on
this matrix, and the run cannot pretend otherwise: the reviewer judged the `VEi` arm only
(`im2_pass_audit.csv` + `im2_failure_audit.csv` → `v34_im2_truth.json`), and the four-way
page's `best_arm` column defaults to `VEi` and was actively marked on 3 cells of 600. The
nearest available signal is v3.3's *both arms failed* verdict — and that BC was BCA4-class,
the build where head subtraction never ran ([v3.4 RESULTS §10](../v3.4/RESULTS.md)). Those
cells are inside the v3.3 half of this union by construction, so the union is the best BC
coverage obtainable without a fresh judging pass. The four named `BC_klein` failures of
v3.0 (`p015+p007`, `dualuse_navy_peacoat_onmodel+p012`, `HD_p023`, `HD_p023+p019`) are on a
different fold and are **not in this matrix at all**.

Both halves are selected on failure, so neither transfers to the fold; the 200-pair run is
link D's job.

## The ankle cut, reopened

v3.4 removed the ankle cut at the lock — its link A found the cut neutral on every failure
class, and v3.4 made footwear a product decision ("the reference keeps its feet"). Link C
reopens it **as its own variable, not as a rider**: each `a` arm (`VEica`, `M1qca`) is
paired with its cut-less twin at the same seed, so the cut is the only difference between
them. The implementation is `run_ironman.ankle_cut` verbatim — MediaPipe's ankle landmarks
on the reference, cut 3% of the height above the lower one, the A4 crop's own ankle ratio
as the fallback — and it is a **no-op by construction** on a reference with no ankles in
frame, which cell 9 counts rather than assumes.

## Link B's set — the pairs v3.4 actually failed

`v3/testsets/v35_failures.csv` — **31 pairs**, every pair of the 200-pair iron-man 2 matrix
on which the locked v3.4 arm `VEi` has a **real failure by the reviewer's own per-cell
verdict** (`v34_im2_truth.json`: 600 cells, 100% human-judged, 79.2% clean / 11.7%
shippable / **9.2% real failure** — [v3.4 RESULTS §10.5](../v3.4/RESULTS.md#105-the-complete-human-verdict--all-600-vei-cells-audited-2026-09-08)). Each row
carries the three per-seed verdicts and whether the failure is seed-stable; **8 of the 31
fail at every seed**, and those are the ones a reference change has to reach.

This is not the v3.4 failure set (`v34_failures.csv`), which was selected on *v3.3's*
failures and predates the lock. Selected on failure either way, so a rate measured on it
does not transfer to the fold — its job is to show whether the head-crop reference reaches
a failure the mannequin reference did not. The 200-pair matrix is link C's job.

Call 2 is the lock's, unchanged: prompt `E3`, fal's own canvas (reproduced by not passing
`image_size`), and the reference **SR'd to ~1 MP first, exactly as `VEi` does it**. The only
variable on the page is which reference call 2 was given.

## Backend

**fal**, `fal-ai/flux-2/klein/4b/distilled/edit`, $0.015/call — the same weights as the
deploy path, on someone else's GPU. Link A is a prompt experiment, and every arm in it is
drawn by the same backend at the same seed, so the comparison is paired and internally
valid. **Any number that goes into a lock is re-measured on the downloaded weights** — fal
priors have failed to transfer to the A100 twice ([v3.4 links F→G](../v3.4/EXPERIMENT.md)).

## Review

Unblinded contact sheets, crop beside all four arms per garment, at
`v3/report/v35_linkA.html`. The question at link A is not "which is prettier" but three
readable facts per cell: did the wearer turn front-on, did the garment survive unchanged,
and is the head gone.
