# v3.13 — TEST

The matrix, per [SCHEMA.md](../SCHEMA.md). Written before the confirming run; the set is
generated by `v3/build/make_v313_set.py` into `v3/colab/v313_set.csv`, and editing that table by
hand is how a run stops matching its specification.

## 1. The candidates

All six are built from models the crop **already loads**. None adds a weight file, a download or
a dependency, which is the constraint that rules out anything else.

| candidate | the test | where it comes from |
|---|---|---|
| `HEAD selfie` | Selfie Multiclass `FACE + HAIR` > 0.6, ≥ 500 px | Ray's suggestion |
| `FACE selfie` | Selfie Multiclass `FACE` > 0.6, ≥ 500 px | `v3lib.tone`'s own test |
| `NOSE pose` | Pose nose landmark, visibility ≥ 0.5 | the shipped tie-break |
| `FACE or NOSE` | either of the two above | **the gate as shipped — the baseline to beat** |
| `HEAD parser` | SCHP ATR classes 1, 2, 3, 11 as a share of all labelled pixels, ≥ 2% | the parser already in the crop |
| `HEAD pose` | both ears and both shoulders at visibility ≥ 0.5 | the skull ellipse's precondition |

Thresholds are the pipeline's existing ones — 500 px and 0.5 visibility are not tuned here, and
the raw measurement behind every verdict is exported so a threshold can be moved without
re-running anything.

## 2. The set

`v3/colab/v313_set.csv` — **73 distinct photographs**, every one a tracked file so the notebook
can fetch it from the branch.

| | images | ground truth |
|---|---|---|
| a person wearing the garment | **56** | the fold's garment stems, `v3/runs/v310/a100/in1mp/` |
| flat-lay or ghost-mannequin | **17** | `kind=garment` with `photo_style` `flat_lay` or `ghost_mannequin` |

**Ground truth is the manifest's own field, not a judgement of the picture.**

**The de-duplication matters.** The 13 `on_model` garments of `test_set1` are a **subset** of the
fold's 56 stems. Adding the two lists without dropping duplicates counts those 13 twice and
reports 86 images, or a "69 worn photographs" denominator that is really 56. The set builder
raises rather than silently double-counting, and an earlier count of the person-free set made
the same mistake in the other direction — 27 product shots that were 17 distinct.

## 3. What counts as a pass

Two errors, and they are not equal:

- **A worn photograph called *no person*.** The garment skips the bald pass it needs, so its
  wearer's head is never removed. **This is the error that matters.**
- **A flat-lay called *person*.** It goes through the pass it does not need — which is exactly
  today's behaviour, so nothing regresses.

A candidate is only interesting if it makes **zero** of the first kind. Among those, fewer of the
second wins, and a wide margin beats a narrow one: a threshold sitting in a gap with nothing near
it will survive photographs this set does not contain, and one sitting 6% from a real image will
not.

## 4. Budget

No image is generated. Six detector passes over 73 photographs — seconds of compute on any GPU
runtime, and no fal, no klein, no cost worth tabulating. The models are fetched by pinned URL and
verified by sha256 in the notebook.

## 5. Protocol

1. Push `v313_bundle.zip` to `v3.3-lock`; the notebook fetches it from GitHub raw.
2. `v3/colab/v313_gate.ipynb` on any GPU runtime, Run all. Cell 5 prints which provider SCHP got,
   because a silent fall back to CPU changes the timing but not the verdicts, and only the
   verdicts are being read here.
3. Unpack the downloaded zip's `meta/v313_measurements.json`, then
   `python3 v3/build/v313_page.py <that file>` → `v3/report/v313.html`.
4. Read the disagreements, which the page floats to the top. Rows where every candidate agrees
   need no attention.

The candidate definitions live in `v3/colab/lib/run_v313.py` and are imported by both the
notebook and the page builder, so the two cannot disagree about what a name means.
