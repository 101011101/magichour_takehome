## Why this run exists

Two open questions collapse into one experiment:

1. **Parity.** Every V2 number so far comes from fal-hosted endpoints. Under the
   parity rule in `execution_conventions.md`, a claim only counts once it is
   reproduced on downloaded weights. No self-hosted run has happened yet, so the
   V2.1 decision is currently unverified in the deploy path.
2. **Which klein.** fal serves both Apache checkpoints, and on Testset2 they tied
   on VLM fidelity at 4.41 while trading different things (V2.1, "klein distilled
   vs klein base"). The tie should be broken on the weights we would actually
   ship, not on two different hosted endpoints with their own preprocessing.

## The run

| arm | checkpoint | sampling |
|---|---|---|
| `klein_4b_edit_sh` | `black-forest-labs/FLUX.2-klein-4B` (distilled) | 4 steps, guidance 0 (distilled: no true CFG) |
| `klein_4b_base_edit_sh` | `black-forest-labs/FLUX.2-klein-base-4B` (undistilled) | 28 steps, guidance 5.0, negative prompt |

- **Set:** Testset2, all 13 pairs (6 product, 4 duo_lookbook, 3 duo_swap).
- **Seed 46**, and the prompt is `prompt_for()` **imported from
  `v2/build/ts2_harness.py`**, not re-implemented — a re-implementation would
  make this a different experiment rather than a parity test.
- **Hardware: free Colab T4.** BFL states ~13GB VRAM for both checkpoints and a
  T4 is 16GB. fp16 (Turing has no bf16) plus sequential CPU offload. The `-fp8`
  and `-nvfp4` repo variants are unusable here — fp8 needs Ada or newer.
- **Notebook:** `v2/virtual_tryon.ipynb` §14. Weights download on a free CPU
  runtime into the Drive HF cache (§14a-c); only §14d needs the GPU.
- **Scoring:** unchanged — `ts2_harness.py --score --judge --html`. The `_sh`
  suffix keeps these rows next to their fal counterparts in the same tables.

## What each outcome means

| Outcome | Reading |
|---|---|
| Both `_sh` arms land near their fal rows | fal was a faithful substrate; every V2 number stands, and the tie-break is decided on the self-hosted numbers |
| `_sh` arms diverge from fal | fal's preprocessing was doing work we did not account for; **the V2.0/V2.1 leaderboards need re-running self-hosted before anything ships** |
| Distilled ≥ base self-hosted | V2.1 stands unchanged |
| Base ≥ distilled self-hosted | The editing base changes to the undistilled checkpoint — which is also the one BFL recommends for LoRA fine-tuning, so it makes the v2.5 fine-tuning path cheaper |

A known confound this run removes: on fal, base-edit inputs are resized to 1MP
while the distilled endpoint keeps larger frames, so the two were never judged at
the same resolution. Self-hosted, both run at the same input size.
