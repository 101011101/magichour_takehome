Short answer: everything measured so far ran on fal. Nothing has yet been run on downloaded weights. fal is used here as a serving substrate for open-weights checkpoints, never as a model source — but that means every number in the V2 scoreboard is still directional, not final, because the parity rule requires reproducing it on self-hosted weights.

Of the four models previously listed as self-host only, one (HiDream-O1-Image) turned out to have gained a fal endpoint and was tested immediately — and eliminated. The other three, plus the highest-priority auxiliary test, genuinely have no hosted path and are still unrun.

Eliminated on three distinct failures, not on a thin average:

  1. It re-renders the frame instead of editing it. Scene 3.62 and background PSNR 14.1 dB against FASHN's 5.00 / 27.5 dB — visible reframing, and pose displacement up to 0.52 where the other arms sit near 0.05.
  2. It no-ops on outerwear. VLM garment 1/5 on three of the four duo_lookbook coats — the input outfit is left untouched while the person and scene are faithfully preserved.
  3. It is the only arm that substituted the reference's person (ts2_08, ts2_11 — AuraFace cosine 0.05 and 0.10 against the input). That is the model2model collapse the benchmark literature predicts and the other three arms avoided through explicit target-garment prompting.

Its one win is VLM realism — 4.08, the top of the board. That is an argument for screening it in the auxiliary bucket, where the job is "make this image more real without changing it", not in the editing bucket.

How the self-host runs would work

The cheap part
Harness integration

The eval pipeline is arm-agnostic. A self-hosted arm only has to write v2/runs/ts2/outputs/{arm}__{id}.png plus its sidecar JSON; then ts2_harness.py --score --judge --html runs locally and the new arm appears in every table and on the comparison page exactly as hidream_o1_edit did today. No harness changes, no re-judging of existing arms (judging is incremental and cached).

The expensive part
Environment and GPU time

A Colab A100 session with HF_HOME pointed at the Drive cache, so each checkpoint downloads once and every later session skips it. Big checkpoints (~40GB class) are copied Drive → VM disk before loading; sub-20GB models load fine straight from the cache. This session has to be built for the parity rule regardless — the queued self-host arms ride along on it rather than being separate work.

The parity gap, stated plainly

Every number on the V2 scoreboard — klein's win included — comes from a fal-hosted endpoint. fal adds its own preprocessing and defaults, so these are directional results that rank arms against each other; they are not the numbers the deployed path will produce. The self-hosted run is not an optional extension arm. It is the step that converts the current results into claims we can ship.
