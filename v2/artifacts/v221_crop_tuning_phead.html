Crop Tuning — PHEAD

Can a fully deterministic crop match the arms that cost a generative call?
38 rows. PHEAD’s reference costs no generative call — only the klein try-on itself, same as every other arm. Shown beside the arms it has to beat. Mark each row perfect / ok / fail.
  • PHEAD is fully deterministic — no generative call at all. It removes only the head, using the human parser’s head classes, and keeps everything else: arms, legs, torso. Subtractive like control (C3.1), but the head mask comes from the parser rather than from MediaPipe HAIR+FACE
  • PCROP is shown faded, for contrast, and is not judged. It took the garment classes directly and therefore dropped the body with them — the same over-crop C4 had. A garment with no body loses the drape and fit context that makes it legible
  • Why this arm exists. Every arm that survived high-damage references needs a generative preprocessing step, which doubles the klein calls. If PCROP holds up it gives that robustness at zero marginal cost per request
  • Measured first, so the cheaper idea was ruled out: merely swapping the better head detector into C3.1 moves it by only +0.5–1 point on haired originals — MediaPipe’s HAIR class already covers a haired head. That swap reproduces control. Taking the garment class directly is the change that is actually different
  • Three verdicts. perfect = as good as the best arm on that row, i.e. it would have been tied first — not a rank · ok = usable, would sit in the ranked middle · fail = unusable
  • Each row shows PHEAD next to the arms it has to beat — control (the incumbent, cut 61% of the time on high-damage), BC_klein and D3B (the two best arms, each costing a generative call), and PCROP faded for contrast. Judge PHEAD, but judge it against these: the question is whether a free arm reaches what the paid ones reach
  • The PHEAD reference is shown too, so a bad result can be blamed on the crop or on the model without leaving the row. Verdicts save to your browser; Save verdicts CSV writes the file to send back
