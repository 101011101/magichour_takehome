Garment Cropping Screen

How good is automatic garment isolation before we spend anything on generation? Everything on this page ran locally on the CPU at zero cost: OpenCV plus two permissively licensed weights — BiRefNet-general (MIT) for the high-resolution subject matte and Selfie Multiclass 256×256 (Apache-2.0) for semantic labels. No API calls, no paid models. 13 unique garment references from v2/runs/ts2/matrix.csv (6 product, 7 duo). Median duo runtime 1s per reference on 4 CPU cores.

Stage 1 — segmentation
BiRefNet at 1024×1024

A high-resolution subject alpha, used exactly as it comes out — nothing is thresholded and no filter is run over it. The old pipeline had no stage like this: it thresholded a 256×256 class map and upsampled it about six times, which is a staircase by construction. Inference is ~4 min per reference on this machine, so the raw output is cached under v2/runs/.cache/matte/ and everything downstream is recomputed on each run in about a second.

Stage 2 — trimap
erode / dilate, class labels only

The class probability — clothes, skin, hair — is thresholded, then eroded and dilated into definite foreground, definite background and an unknown band. This is the boundary that is genuinely vague, because it is the one still coming from the 256×256 map. The subject silhouette gets no trimap.

Stage 3 — matting
guided solve, internal edge only

Inside the unknown band, a guided filter against the full-resolution image turns the class label into a real 0-1 alpha, so clothes-against-skin is soft rather than stair-stepped. Running the same solve over the subject matte was tried and reverted: it punched white speckles about 15px into the navy peacoat's sleeve, because guided filtering transfers image structure into the alpha and dark fabric on a white ground is the worst case for that. High-resolution segmentation alone was the whole fix for the outer edge.

How the two models compose

BiRefNet defines what the subject is; Selfie Multiclass defines which part is which. Class alpha is multiplied into the matte and only ever subtracts from it, so the outer silhouette in every variant is the high-resolution one and never the 256×256 map. The composition is subtractive for that reason: C3 is the matte minus the head, C4 is C3 minus body skin. Intersecting with the clothes class instead was tried and it notched 6px blocks out of the peacoat's outline, because at the silhouette that class is exactly as coarse as the map it came from. Product references (flat-lay, ghost mannequin) skip BiRefNet entirely — corner-seeded colour distance is already exact at full resolution there — but they run the same trimap and matting stage so the edge is an alpha, not a label.

The four variants

All four are whole-subject crops — the subject bounding box plus a 3% margin, identical across variants so they stay registered. There is no shoulders-to-hips or hips-down band any more: the band prior was what dragged the jeans into the navy peacoat crop, and deciding which garment to change is the prompt's job, not the cropper's. A select_region knob is stubbed and defaulted off for a future selectable version.

C1 bbox box crop, background untouched · C2 bbox_nobg background white, wearer kept · C3 no_face background white and the head removed (hair + face skin), body skin kept · C4 clothes_only every clothing class — coat, trousers, shoes, accessories — with all skin and the face removed. The face is the thing that most needs to go, it is a second identity in the frame, while removing every scrap of skin may cost more than it buys; C3 against C4 is the next test. Everything that could be sent to a model is flattened onto white by us against the real alpha: an endpoint that flattens alpha to black would be much worse than white, so we never hand one an alpha channel.
